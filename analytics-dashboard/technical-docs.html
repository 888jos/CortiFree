🚀 Onboarding Flow (16 Steps)

▶
1. Welcome Screen ↓ 2. Overall Quiz (5 questions) Gender, Age, Discovery, Stress Reasons, Duration ↓ 3. Reassurance ↓ 4. Habits Quiz (11 questions) ⭐ CRITICAL → Calculates 6 domain scores (0-100) → Saved to Firestore ↓ 5. 60-Day Explanation ↓ 6. Scientific Plan ↓ 7. Authentication ⚠️ HIGH DROP-OFF Email/Password or Google Sign-In ↓ 8. Loading Analysis (fake 3s) ↓ 9. CortiFree Rating Display calculated scores with animation ↓ 10. 8 Habits Intro ↓ 11. Week Progress ↓ 12. 8 Habits Flow (Carousel) ↓ 13. Notification Permissions ↓ 14. Habits Progress (Charts) ↓ 15. Social Proof (Testimonials) ↓ 16. Paywall ⚠️ HIGH DROP-OFF 3-day free trial RevenueCat or Custom paywall ↓ ✅ COMPLETED (onboardingCompleted = true)

Conversion Metrics:

Step Avg Completion Note
Welcome → Overall Quiz ~85% Good
Overall Quiz → Habits Quiz ~65% Normal
Habits Quiz → Authentication ~45% ⚠️ Drop-off
Authentication → Paywall ~25% Critical
Paywall → Completed ~20% Critical

🔄 Core Loop (Daily Task Completion)

▶
User completes task ↓ ImpactScoringService.applyTaskImpact(habitId) → Updates Firestore currentDomainScores → Serenity +2.0, Sleep +1.0, etc. ↓ FirebaseService.completeTask() → +5 XP → Update dailyPrograms collection ↓ Check Milestones → 3, 7, 14, 30, 66 days? → Unlock achievement badge → Send notification ↓ MixpanelManager.trackTaskValidated() → Firebase Analytics → Firestore analytics_events ↓ Update UI → Global score increases → Streak counter updates → XP bar fills → Confetti animation (100%)

Priority Recommendations

Ranked action items for new developers

🔴 P0 - Critical Understand Core Loop First

▶

Why: This is the heart of the app. Everything revolves around task completion.

Flow to understand:

User swipes right on task
   → TasksViewModel.validateTask()
   → ImpactScoringService.applyTaskImpact(habitId)
   → FirebaseService.completeTask() (+5 XP)
   → Check milestones
   → MixpanelManager.trackTaskValidated()

Files to read:

  • TasksViewModel.swift (lines 257-305)
  • ImpactScoringService.swift
  • FirebaseService.swift (lines 117-135)

🔴 P0 - Critical Respect MVVM Architecture

▶

Rule: Views never talk to Firestore directly. Always use Services via ViewModels.

❌ WRONG:

// In SwiftUI View
let db = Firestore.firestore()
db.collection("users").document(userId).setData(...)

✅ CORRECT:

// In View
@StateObject private var viewModel = TasksViewModel()

// In ViewModel
await firebaseService.saveTask(task)

// In Service
FirebaseService.shared.saveTask(_:)

🟡 P1 - High Analytics are Mandatory

▶

Every screen MUST track:

.onAppear {
    MixpanelManager.shared.track(event: "screen_name_viewed")
}

Every CTA button MUST track:

Button("Action") {
    MixpanelManager.shared.track(
        event: "action_clicked",
        properties: ["key": "value"]
    )
    // Action logic
}

🟡 P1 - High Refactor: Unify Firebase Services

▶

Problem: 3 overlapping Firebase services exist:

  • FirebaseService.swift
  • FirebaseManager.swift
  • OptimizedFirebaseService.swift

Solution: Consolidate into UnifiedFirebaseService

UnifiedFirebaseService
  ├─ AuthModule (replaces AuthService + AuthManager)
  ├─ FirestoreModule (replaces FirebaseService + Manager)
  └─ AnalyticsModule (wraps MixpanelManager)
